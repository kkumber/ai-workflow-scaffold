# Phase documents

- One Markdown file per agreed phase: `PHASE-01-short-name.md`, `PHASE-02-short-name.md`.
- Use the [phase specification form](../../tasks/_template/plans.md#phase-specification-template); preserve stable IDs.
- Link phase files from the [PROJECT.md roadmap](../../PROJECT.md#implementation-plan-by-phases).
- Include scope, feature/goal IDs, dependencies, sequencing, entry/exit criteria, risks and task links.
- Task plans retain cases, approvals and execution evidence; phase files summarize progress and handoffs.
- Read only the selected phase and relevant dependencies; reuse unchanged context.
- This scaffold has no receiving-application phases to populate. AI setup creates the project-owned phase files after clarification; this source layout guide is not copied by the initializer.
